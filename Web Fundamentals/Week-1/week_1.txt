============================================================
1. CLIENT–SERVER MODEL
============================================================

CONCEPT
A client requests a service/resource and a server provides/processes it.

Basic flow:

    Client → Request → Server
    Client ← Response ← Server

The browser is a client.
Django's development server is a server.
`curl` is also a client.

------------------------------------------------------------
1.1 Start a simple local server
------------------------------------------------------------

COMMAND:

    python -m http.server 8000

WHAT IT DOES:
Starts a simple HTTP server on your machine on TCP port 8000.

WHAT TO OBSERVE:
- The server is listening for incoming HTTP connections.
- The terminal should show a message similar to:
  "Serving HTTP on ... port 8000"

Do not close this terminal while testing.

PASTE OUTPUT:

----- OUTPUT START -----
Serving HTTP on 0.0.0.0 port 8000 (http://0.0.0.0:8000/) ...
----- OUTPUT END -----

2. IP ADDRESSES
============================================================

CONCEPT
An IP address is used to identify a network endpoint/address for IP communication.

Examples:
- 127.0.0.1  → IPv4 loopback
- 192.168.x.x → common private IPv4 range
- IPv6 addresses look different, for example: 2001:db8::1

Remember:
    IP address → network destination/address

------------------------------------------------------------
2.1 View all network interfaces and addresses
------------------------------------------------------------

COMMAND:

    ip addr

SHORT VERSION:

    ip a

WHAT TO OBSERVE:
Find:
- `lo` → loopback interface
- Your Wi-Fi interface, often starting with `wl...`
- `inet` → IPv4 address
- `inet6` → IPv6 address
- `state UP` / `state DOWN`

QUESTIONS:
1. What is the name of your Wi-Fi interface?
2. What IPv4 address does it have?
3. What IPv4 address does `lo` have?

3. PORTS
============================================================

CONCEPT
An IP address identifies the network destination.
A port identifies a service/application endpoint on that host.

Example:

    127.0.0.1:8000
    IP       : port

Think:
    IP   → where?
    Port → which service?

------------------------------------------------------------
3.1 View listening TCP and UDP ports
------------------------------------------------------------

COMMAND:

OPTIONS:

    -l  listening sockets
    -n  numeric addresses/ports

WHAT TO OBSERVE:
Look for lines such as:

This means something is listening on TCP port 8000 on the loopback interface.

4. TCP / UDP
============================================================

CONCEPT
TCP and UDP are transport-layer protocols.

TCP:
- Connection-oriented
- Reliable
- Ordered byte stream
- Retransmission is handled by TCP

UDP:
- Connectionless datagrams
- No delivery guarantee from UDP itself
- No ordering guarantee from UDP itself
- Lower transport overhead

Simple memory rule:

    TCP → reliable ordered transport
    UDP → lightweight datagram transport

------------------------------------------------------------
4.1 Observe TCP listening sockets
------------------------------------------------------------

COMMAND:

    ss -ltn

WHAT TO OBSERVE:
Look for `LISTEN` entries.

A TCP server listens for incoming connections.

5.6 Reverse DNS lookup
------------------------------------------------------------

First resolve a domain:

    dig A google.com

Take one IPv4 address from the ANSWER SECTION.

Then run:

    dig -x <IP_ADDRESS>

Example format only:

    dig -x 192.0.2.1

Do NOT use the example address unless it is actually yours.

CONCEPT:
Forward lookup:
    name → IP

Reverse lookup:
    IP → name (when a PTR record exists)
